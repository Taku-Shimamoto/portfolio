ゲーム内容

ゲーム説明

ありそうでなかった「ひらがなのドラフト指名」！

チーム対抗戦形式のしりとりリレーでその速さを競うゲームです。ただし、チームが使う文字はドラフト制で決定！

ひらがなだからこそ覚えやすく遊びやすい。ひらがなだからこそ戦略の幅が広く奥深い。シンプルイズベストの最高到達点を目指しました！

主目的

  • チーム内で誰がどの文字を担当するかを臨機応変に決め、その役割を遂行する(役割遂行)
  • どの文字を選び、どの文字をBANするかを話し合い決定する(戦略、コンセンサス)
  • 与えられた文字しか使えない状況で、制限時間内にその状況に合う言葉選びをする(ひらめき力)

遊び方

推奨人数

10人(8人～14人まで対応)

所要時間

1ラウンド約5分

必要なもの

  • 本ゲームアプリ
  • ホワイトボード
  • 水性ペン
  • ひらがなの書かれたカード(「あ」～「ん」まで2枚ずつ ※なくても十分に楽しめます)

手順

通常モード(練習用)
  1. BANフェーズ: ランダムで4文字が使用禁止として選ばれます。

    ※通常モードにおいてはあまり意味を持ちませんが、ドラフトモードへの導線として、形式上BANピックを行います。

  2. 文字選択フェーズ: 各チームで人数+1個の文字がランダムで選ばれます。

    選ばれた文字と同じひらがなカードを引きます。

  3. シンキングタイム: 30秒のシンキングタイムをとります。

    この間はチームで話し合ったり、ひらがなカードを並べ替えたりすることができますが、ホワイトボードに書くことは禁止です。

  4. しりとりリレー開始: 90秒以内に、ホワイトボードを使い、しりとりリレーを完成させましょう。
    • 与えられた文字をすべて使い切ります。
    • 誰が、どの文字を、どの順番で使用しても構いません。
    • 「ん」または「ー」を持っている場合、必ず最後に使用します。
    • 順番変更、書き直しは何度でもできます。

    例：「し」「ま」「も」「と」「た」「く」の6文字が与えられた場合

    たいいく → くちばし → しろくま → まりも → もるもっと

    でリレーが完成します。

  5. ポイント集計: 90秒以内にホワイトボードに書いた単語の数のぶんだけポイントになります。

    90秒以内に両チームともリレーを完成させた場合は、早かった方に追加で1ポイントが与えられます。

ドラフトモード(ルールに慣れたらこちらに移行)
  1. ランダム文字選択フェーズ: 各チームにランダムで選ばれた1文字が与えられます。
  2. BANフェーズ: 各チームは2文字ずつ、合計4文字を使用禁止として選びます。選ばれた文字はそのラウンド中、両チームとも使用できません。
  3. 文字選択フェーズ: 各チームは交互に1～2文字ずつ選びます。
  4. シンキングタイム: 通常モードと同じです。
  5. しりとりリレー開始: 通常モードと同じです。
  6. ポイント集計: 通常モードと同じです。

制作を振り返って

このゲームはこれまで作ったどのゲームアプリやスクリプトよりも難しく、時間のかかるものでした。しかし、制作過程で得られた学びもその分とても大きいものでした。

このゲームにおいての核となる部分は「状態管理」です。モード、フェーズ、チーム、ピック状況、タイマーなど、いくつもの状態が入り組んでおり、しかもゲームの進行に合わせて頻繁に変化していきます。これらの状態をどのように制御するのか、というのがこのゲームの実装における課題であることは、制作開始からすぐに分かりました。

Before
// (例) チーム名を呼び出したいとき、チームが切り替わると、その都度元データの参照も変えなければならない
// これがかなり手間がかかる上、不具合が起きたときにどこの状態管理に原因があるのかを追求するのが大変...
const TEAMS = {
    team1: {
        name: "チーム1",
        ...,
    },
    team2: {
        name: "チーム2",
        ...,
    },
};

let currentTeam = "team1";
let currentTeamName = TEAMS[currentTeam].name;

currentTeam = "team2";
currentTeamName = TEAMS[currentTeam].name;  // これがないとUIや参照は「チーム1」のまま
After
const gameStates = {
    currentTeam: "team1",

    get team() {
        return TEAMS[this.currentTeam];
    },
};

function switchTeam() {
    gameStates.currentTeam = gameStates.currentTeam === "team1" ? "team2" : "team1";
}

const currentTeamName = gameStates.team.name;

この課題を打破したのは、オブジェクトにおける「ゲッター」という概念でした。オブジェクトが呼び出されるたびに、定義されたゲッター関数によって参照が最新の状態に更新されるようになります。状態管理の責務はすべて各ゲッター関数とそれらをまとめるgameStatesの中に閉じ込められるため、ステップ処理やチーム切り替えについての不具合の原因特定がしやすくなります。制作過程で新たなステップ処理や状態を追加することがあった際も、gameStatesに状態やゲッターを追加することが基本となるため、保守性と拡張性の面で大いにその恩恵を受けることになりました。
